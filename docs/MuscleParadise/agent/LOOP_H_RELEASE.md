# LOOP H — انتشار و تحویل
## ۱۴ تسک (+۱ اختیاری) · ~۱.۵ هفته · وابسته به همهٔ لوپ‌ها

**هدف:** چهار فایل نصبی امضاشده که یک مربی غریبه بتواند بدون کمک نصب و استفاده کند.

---

## H-01 · یک منبع واحد نسخه
| **مشکل** | `package.json` و `app/__init__.py` دستی نگهداری می‌شوند = واگرایی حتمی |
|---|---|
یک فایل `VERSION` در ریشه؛ بقیه از آن بخوانند. تستی که همگامی را بسنجد.

## H-02 · معنای SemVer برای این محصول
```
MAJOR = شکستن قرارداد API یا مهاجرت غیرقابل‌بازگشت DB
MINOR = قابلیت جدید سازگار
PATCH = رفع اشکال
```

## H-03 · 🔴 پشتیبان خودکار قبل از مهاجرت
**الزام قبل از v1.0.** هر انتشار باید **قبل** از اعمال مهاجرت خودکار پشتیبان بگیرد
و اگر مهاجرت شکست خورد، **خودکار برگردد**.
۵۰ خط کد که از یک فاجعهٔ داده جلوگیری می‌کند.
**verify:** تست: مهاجرت عمداً شکسته → DB به حالت قبل برمی‌گردد

## H-04 · جادوگر اولین اجرا
نام باشگاه · **رمز مالک (اجباری، H-05)** · تنظیم تقویم/واحد · نصب پک اختیاری.
**هدف: از نصب تا داشبورد < ۵ دقیقه.**

## H-05 · اجبار رمز قوی مالک
تکمیل A-05 در سطح نصب‌کننده. `1111` هرگز نباید به تولید برسد.

## H-06 · دود تست نصب واقعی ویندوز
نصب روی VM تازه → اجرا → ورود → یک عملیات → حذف نصب.
**نصب‌کننده‌ای که روی ماشین تمیز آزموده نشده، آزموده نشده.**

## H-07 · دود تست نصب APK
روی امولاتور: نصب → کشف سرور → ورود → اسکن QR.

## H-08 · SBOM
CycloneDX برای Python و npm — ممیزی مجوز (C9) با ابزار، نه حدس.

## H-09 · امضای cosign
هر آرتیفکت + SHA256SUMS.

## H-10 · تولید خودکار یادداشت انتشار
از بخش نسخه در `CHANGELOG.md`. **هر ورودی باید عدد اندازه‌گیری‌شده داشته باشد** (C12).

## H-11 · گردش‌کار انتشار
`.github/workflows/mp-release.yml` روی تگ `v*`:
```
۱. همهٔ دروازه‌های ci.yml سبز (وگرنه توقف)
۲. ساخت چهار هدف + پک
۳. SHA256SUMS + cosign + SBOM
۴. یادداشت از CHANGELOG
۵. آپلود به GitHub Release
```

## H-12 · راهنمای فارسی مالک
نصب · اولین اجرا · پشتیبان · بازیابی · به‌روزرسانی · عیب‌یابی.
**با تصویر.** مالک باشگاه DevOps نیست.

## H-13 · ابزارهای عملیاتی به‌صورت دکمه
| کار | وضعیت امروز |
|---|---|
| پشتیبان دستی | API هست، دکمه نیست |
| مشاهدهٔ فضای دیسک و سلامت | ندارد |
| به‌روزرسانی یک‌کلیکی | بدون تأیید امضا |
| صادرات همهٔ داده | ندارد |

## H-14 · اسکریپت بازگشت نسخه
اگر انتشار خراب بود: بازگرداندن باینری + مهاجرت `down()` + بازیابی پشتیبان.
**آزموده شده، نه فرضی.**

## (اختیاری) H-15 · استقرار Dokploy
فقط برای باشگاه‌های چندشعبه‌ای که آگاهانه ابر می‌خواهند:
Traefik (TLS خودکار) → کانتینر هسته → حجم پایدار.
تصویر چندمرحله‌ای · کاربر غیر-root · `HEALTHCHECK`.
⚠️ **هرگز پیش‌فرض نشود** — C1/C2 اصل محصول است.
اگر متمرکز شد، SQLite کافی نیست → Postgres (build/02 §9).
