۱) P0 — گیت digest یک حالت کور دارد (این را خودم پیدا کردم)
────────────────────────────────────────────
`verify_crosswalk_digests.py` تابع `inspect_stale()` را برای فایل‌های STALE دارد.
خط ۱۵۰–۱۵۵:

      actual = actual_digest(SOURCE_ROOT / relative)   # → None اگر فایل نباشد
      expected = recorded_hex(recorded)                # → None اگر مقدار خراب باشد
      report.append(f"... actual={shorten(actual)}{'' if actual == expected else '  ← کهنه'}")

اگر **هم** digest ثبت‌شده خراب باشد و **هم** فایل در checkout نباشد:
`None == None` → هیچ `← کهنه` چاپ نمی‌شود. من تست کردم:

      $ # فایل را پاک کردم و digest را "garbage-not-a-digest" گذاشتم
      STALE …/appStore.ts recorded=missing actual=missing
      EXIT=0

یعنی یک artifact کهنه که هم منبعش رفته و هم digestش خراب است، **سالم** گزارش می‌شود.
این دقیقاً همان دسته باگی است که کل این گیت برای گرفتنش ساخته شد.

نکتهٔ مهم: مسیر **غیر-STALE** این باگ را ندارد — آنجا `expected is None` و
`actual is None` هر دو `problems.append` می‌شوند. فقط `inspect_stale` این را ندارد.

کار:

  الف) در `inspect_stale`، همان دو بررسی را اضافه کن:

        if expected is None:
            problems.append(f"{artifact}: {relative} digest نامعتبر ({recorded!r})")
        if actual is None:
            problems.append(f"{artifact}: {relative} در checkout نیست")

      (کپی مستقیم از `check()` — همان منطق، دو خط.)

  ب) سه تست رگرسیون در `tests/` یا هر جای مناسب:
        1. STALE + فایل موجود + digest کهنه → خروجی «← کهنه»، `EXIT=0` (گزارش، نه fail)
        2. STALE + فایل غایب → `EXIT=1`
        3. STALE + digest خراب → `EXIT=1`

      بدون این سه، هر کسی فردا می‌تواند با `git rm` یک منبع، گیت را بی‌صدا کند.

۲) P1 — ادعای «درخت شاخه بایت‌به‌بایت برابر main است» نادرست است
────────────────────────────────────────────
نوشتی: «`git diff origin/main HEAD` خالی».

واقعیت (من از API گرفتم):

      main tree  : 7efb632386b7e8e46ca1d16ab9563799aa382b24
      branch tree: 7f369e26f6234150a6781714ed811850b1c978d5
      compare(main...branch): ahead=15 behind=0 files=19
      +276 / −75 خط

۱۹ فایل تفاوت دارند — همان برش MEM-06 و اصلاح STALE. این **درست و مورد انتظار**
است؛ PR برای همین باز شده. ادعای «برابر است» مشکل دارد، نه تفاوت.

شاید `git diff origin/main HEAD` را در checkout محلی گرفتی که `origin/main` آن
قدیمی/غایب بود (اگر `git fetch` نکرده باشی، `origin/main` روی `ebebef3` می‌ماند —
ولی حتی آن هم خالی نمی‌دهد). هر چه بود، **این دستور را در گزارش ننویس مگر با
خروجی واقعی‌اش**.

کار: در STATE و گزارش‌های بعدی، «برابر» را با tree SHA یا با
`git rev-list --count` بنویس، نه با «diff خالی». مثلاً:

      BRANCH_VS_MAIN: ahead=15 behind=0 · tree differs=yes (expected)
      MERGE_BASE_SYNC: main@7c4771f is ancestor → yes
