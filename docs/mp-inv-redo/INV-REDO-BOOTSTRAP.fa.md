> پیشین ساخته و **push نشد** و از بین رفت، به یک مسیر **قابل تکرار و قابل اثبات** تبدیل می‌کند.
> هیچ‌جا ادعا نمی‌کنیم نسخهٔ گم‌شده را بازگردانده‌ایم؛ متن آن در دسترس نیست. چیزی که

>
> **وضعیت:** ابزار تست‌شده روی `main` (`3527810`) اجرا شد و خروجی نمونه در

## ۱. چرا کار قبلی از بین رفت (تشخیص، نه حدس)

| نشانه در گزارش بیلدر | واقعیت روی GitHub (بررسی‌شده) |
|---|---|
| `HEAD=e0ae95f4…` | چنین commitی در مخزن وجود ندارد |
| `evidence/2026-11-23/INV-02/…` | نه روی `main` و نه روی `arena/5e0f64cf-mp` — فقط `evidence/m60/` هست |
| «۲۴ tracked + ۳۰۹ untracked» | یعنی همه‌چیز در worktree محلی مانده |
| «نه commit شد نه push» | نقطهٔ قطع؛ با بسته‌شدن نشست، worktree از دست رفت |

**درس ساختاری:** در این پروژه، worktree محلی حافظهٔ پایدار نیست. تنها حافظهٔ پایدار
commit روی ریموت است. پس هر ابزار تولید شاهدی باید **دوباره‌اجراشدنی از روی SHA** باشد،
نه یک فایل دست‌نویس که فقط یک‌بار وجود داشته.

| فایل | نقش |

هر دو اسکریپت **هیچ فایلی جز خروجی خودشان نمی‌نویسند** و هیچ‌جا `CURRENT` صادر نمی‌کنند.
سقف ممکن `PARTIAL_REVIEW` است، چون مجوز سمت سرور با تست منفی اثبات نشده.

## ۳. قواعد سختی که جلوی تکرار فاجعه را می‌گیرد

1. **کار قبل از push تمام‌نشده است.** `PARTIAL` بمان، نه `DONE`.
2. **خروجی اسکریپت روی worktree dirty** به SHA نسبت داده نمی‌شود؛ اسکریپت خودش هشدار می‌دهد.
3. **شاهد = فایل commit‌شده روی ریموت**، نه مسیر محلی. بعد از push با
   `git ls-remote` / API contents چک کن.
4. **عدد را از خروجی بگیر، نه از حافظه.** شمارش‌ها در `meta` ذخیره می‌شوند و در JSON هم می‌آیند.
5. **`CURRENT` ممنوع** تا تست منفی (عضو A → دادهٔ عضو B) اجرا و ثبت شود.

## ۴. دستور اجرا (بیلدر)

```bash
# ۱) SHA امن‌شده، نه شاخهٔ محلی خودت
git fetch origin
git checkout --detach origin/main
SHA=$(git rev-parse HEAD)

# ۲) ابزار را از Chat2DB بردار یا از همین پاکت کپی کن
bash scripts/run-inv-redo.sh "$SHA"

# ۳) خروجی را ببین؛ اگر dirty نبود و اعداد منطقی بود:
git add scripts/inv02_member_crosswalk.py scripts/inv03_staff_crosswalk.py \
        evidence/$(date -u +%F)/INV-02 evidence/$(date -u +%F)/INV-03
git commit -m "INV-02/03: generated crosswalks on $SHA — evidence: scripts/run-inv-redo.sh"
git push origin HEAD:arena/<session>-mp

# ۴) تأیید وجود شاهد روی ریموت (بدون این، کار تمام نیست)
git ls-remote origin | grep <session>
```

> اگر `git checkout --detach` مجاز نیست یا شاخهٔ کار خودت dirty است، همان SHA را در یک
> `git worktree add /tmp/inv $SHA` جدا اجرا کن؛ خروجی را از آنجا کپی کن.
