# 09 — سیستم طراحی و UI/UX

> پایه: `mp-app/DESIGN_SYSTEM.md` + `mp-app/studio/src/styles/tokens.css` +
> `docs/MuscleParadise/design-system/muscle-paradise/MASTER.md`.

---

## 1. تعارض بنیادین — و حل درست آن

نقشهٔ کار خواستار «حرکت سینمایی» بود؛ سند محصول دیال حرکت را برای داشبوردهای پرداده
روی **۴/۱۰** گذاشته بود. تیم این را حل کرده و **حل درستی است**:

| سطح | دیال | قواعد |
|-----|------|-------|
| صفحهٔ فرود، ورود، مودال، توست، جشن دستاورد | **8/10** | spring، `back.out`، ورود مرحله‌ای |
| داشبورد، جدول، فرم، فهرست | **4/10** | fade ۲۰۰ms، بدون مقیاس ردیف، بدون spring |

**اصل حاکم:** حرکت باید **معنا** حمل کند، نه توجه بدزدد.
مربی هشت ساعت در داشبورد کار می‌کند؛ هر انیمیشن اضافه، مالیات شناختی است.
ورزشکار سی ثانیه در اپ است؛ آنجا لحظهٔ احساسی ارزش دارد.

`prefers-reduced-motion` در سه فایل تست پوشش داده شده ✅ — این را هرگز حذف نکنید.

## 2. توکن‌های طراحی

منبع واحد: `styles/tokens.css` (۳.۹۱ kB، gzip ۱.۳۹ kB).

**قوانین الزام‌آور:**
1. هیچ رنگ، فاصله یا شعاع هارد-کد در کامپوننت. فقط `var(--...)`.
   با stylelint اجبار کنید: `declaration-property-value-disallowed-list`.
2. مقیاس فاصله: پایهٔ ۴px (`4, 8, 12, 16, 24, 32, 48, 64`). هیچ عدد میانی.
3. مقیاس تایپوگرافی: نسبت ۱.۲ (Minor Third) — برای رابط‌های پرداده مناسب‌تر از ۱.۲۵.
4. رنگ‌های معنایی، نه توصیفی: `--color-danger` نه `--color-red`.

### 🔴 کاری که هنوز نشده: ممیزی کنتراست
هیچ سنجش کنتراستی روی توکن‌ها ثبت نشده. یک بار با ابزار بسنجید و جدول را اینجا قفل کنید:

| ترکیب | نسبت | WCAG AA |
|-------|------|---------|
| متن اصلی / پس‌زمینه | ؟ | نیاز ≥ 4.5 |
| متن ثانویه / پس‌زمینه | ؟ | نیاز ≥ 4.5 |
| متن روی دکمهٔ اصلی | ؟ | نیاز ≥ 4.5 |
| حلقهٔ فوکوس / پس‌زمینه | ؟ | نیاز ≥ 3.0 |

پالت تیره (`#0B0F14` به‌عنوان پس‌زمینهٔ اصلی) شروع خوبی است، ولی «تیره و باکلاس»
اغلب یعنی «متن خاکستری کم‌کنتراست». حتماً بسنجید.

## 3. تایپوگرافی فارسی

- فونت محلی `PersianSans-Regular.ttf` ✅ — مطابق local-first، بدون Google Fonts.
- **نیازها:** حداقل سه وزن (Regular / Medium / Bold). یک وزن یعنی سلسله‌مراتب بصری ضعیف.
- ارتفاع خط برای فارسی سخاوتمندتر باشد: ۱.۷ برای متن بدنه (نه ۱.۵ که برای لاتین است) —
  کشیدگی‌ها و اعراب فضا می‌خواهند.
- **اعداد:** ارقام فارسی فقط در نمایش. ورودی و ذخیره لاتین. یک `toFaDigits()` در لایهٔ نمایش.
- **زیرمجموعه‌سازی (subsetting):** فونت را به کاراکترهای واقعاً استفاده‌شده محدود کنید
  (`pyftsubset`) — معمولاً ۷۰٪ کاهش حجم.

## 4. RTL — قواعد مهندسی

```css
/* ❌ ممنوع */          /* ✅ درست */
margin-left: 8px;       margin-inline-start: 8px;
padding-right: 16px;    padding-inline-end: 16px;
text-align: left;       text-align: start;
left: 0;                inset-inline-start: 0;
border-left: ...;       border-inline-start: ...;
```
با یک قاعدهٔ stylelint اجبار کنید. بدون آن، افزودن انگلیسی در آینده = بازنویسی کل CSS.

**استثناها که باید LTR بمانند:** اعداد، کد عضویت، شمارهٔ تلفن، محورهای نمودار،
و بلوک‌های کد. با `dir="ltr"` نقطه‌ای علامت بزنید.

## 5. کتابخانهٔ کامپوننت — چه بسازیم، چه قرض بگیریم

اکنون کامپوننت‌ها دست‌ساز و سبک‌اند (خوب برای بودجهٔ باندل).

| نیاز | توصیه | چرا |
|------|--------|-----|
| پایهٔ دسترس‌پذیر (دیالوگ، منو، تب) | **Radix UI Primitives** | بدون استایل، a11y درست، tree-shakable |
| استایل | همان توکن‌های CSS فعلی | Tailwind لازم نیست؛ حجم اضافه می‌کند |
| حرکت | **Framer Motion** ✅ (موجود) | فقط از `presets.ts` استفاده شود |
| نمودار | **SVG دست‌ساز** به‌جای Recharts | ۱۱۱ kB برای یک نمودار خطی توجیه ندارد |
| آیکون | **Phosphor** (کاتالوگ در `tools/ui-ux-pro-max`) | مجوز MIT، وزن‌های متعدد |

**دربارهٔ DaisyUI / Skiper UI / Vengeance UI و مشابه:** این‌ها را به‌عنوان
**مرجع الهام بصری** استفاده کنید، نه وابستگی زمان‌اجرا. هر کتابخانهٔ UI که اضافه کنید
باید از سه فیلتر بگذرد: (۱) RTL بومی، (۲) < ۲۰ kB gzip، (۳) مجوز مجاز.
DaisyUI مثلاً Tailwind را واجب می‌کند — برای این پروژه که CSS خالص و سبک دارد، معامله بدی است.

## 6. صفحهٔ فرود سینمایی

اینجا جایی است که دیال ۸/۱۰ آزاد است. اما با انضباط:

| اصل | اجرا |
|-----|------|
| بودجه | LCP < 2.0s حتی با انیمیشن — تصاویر `webp`/`avif`، ویدیو `poster` |
| حرکت هدفمند | ورود مرحله‌ای (stagger 60ms)، parallax ملایم، نه بیشتر |
| ذرات (particles) | فقط اگر روی موبایل میان‌رده > ۵۰fps بماند؛ وگرنه حذف |
| کاهش حرکت | نسخهٔ ایستا کاملاً کارآمد |
| بدون JS | محتوای اصلی و CTA باید بدون JS دیده شوند |

**قانون سخت:** صفحهٔ فرود هرگز نباید باندل اپ اصلی را سنگین کند. مسیر جدا، چانک جدا.

## 7. الگوهای UX خاص این محصول

### 7.1 کیوسک
- هدف لمسی ≥ ۶۰px (دست عرق‌کرده، عجله).
- بازخورد در < ۲۰۰ms، بزرگ و رنگی: سبز «خوش آمدی نسیم» / قرمز «عضویت منقضی».
- خروج فقط با PIN ✅، بازگشت خودکار به حالت آماده پس از ۸ ثانیه.
- **هرگز** نام کامل و عکس را روی صفحهٔ عمومی کیوسک برای مدت طولانی نگه ندارید (حریم خصوصی).

### 7.2 نمایش مصدومیت
این حساس‌ترین سطح UI است:
- یادداشت بالینی **هرگز** به ورزشکار نشان داده نشود (سمت سرور ماسک می‌شود ✅).
- به ورزشکار «چه نکن» نگویید، «چه بکن» بگویید: به‌جای «اسکات ممنوع» →
  «به‌جای اسکات، پرس پا با دامنهٔ محدود».
- بنر مصدومیت در Studio باید **قبل** از ساخت برنامه دیده شود، نه بعدش.

### 7.3 ثبت ست تمرین
- ورودی عددی بزرگ با دکمهٔ `+`/`−`، نه کیبورد کامل.
- **ذخیرهٔ خودکار محلی** — ورزشکار وسط ست، شبکه قطع، داده نباید برود
  (اکنون نمی‌شود — سند ۰۴ §۴).
- ست قبلی به‌عنوان placeholder: «دفعهٔ قبل: ۶۰kg × ۸».

### 7.4 پول و تاریخ
- ریال با جداکنندهٔ سه‌رقمی و ارقام فارسی: «۱٬۵۰۰٬۰۰۰ ریال».
- تاریخ جلالی همیشه، با نمایش نسبی برای موارد نزدیک: «۳ روز دیگر منقضی می‌شود».
- انقضای عضویت با کدرنگ: > ۱۴ روز سبز، ۳–۱۴ کهربایی، < ۳ قرمز.

## 8. چک‌لیست پذیرش هر صفحهٔ جدید

هیچ صفحه‌ای بدون این ۱۰ مورد ادغام نمی‌شود:

```
□ حالت loading (skeleton، نه اسپینر)
□ حالت خالی با اقدام پیشنهادی
□ حالت خطا با متن فارسی قابل‌فهم + دکمهٔ تلاش دوباره
□ ناوبری کامل با کیبورد + حلقهٔ فوکوس مرئی
□ vitest-axe بدون نقض
□ RTL با ویژگی‌های منطقی (بدون left/right)
□ prefers-reduced-motion محترم
□ حرکت فقط از motion/presets.ts
□ رنگ‌ها فقط از توکن‌ها
□ چانک ≤ ۶۰ kB gzip
```

## 9. استفادهٔ درست از منابع OSS طراحی

فهرستی که دادید (21st.dev، Framer Motion، Origin UI، Skiper UI، Awesome Claude Design، …)
ارزشمند است — اما به‌عنوان **کتابخانهٔ الگو**، نه وابستگی:

1. **الگو را ببینید، کد را بازنویسی کنید.** یک micro-interaction از 21st.dev را
   با توکن‌های خودتان و در `presets.ts` پیاده کنید. کپی مستقیم = وابستگی و مجوز ناشناخته.
2. **هر الگوی پذیرفته‌شده را در این سند ثبت کنید** با منبع و دلیل انتخاب.
3. **فیلتر سه‌گانه** قبل از هر وابستگی جدید: RTL بومی؟ < ۲۰ kB؟ مجوز مجاز؟
4. کاتالوگ موجود در `docs/MuscleParadise/tools/ui-ux-pro-max/data/` (رنگ، فونت، آیکون،
   حرکت، عملکرد React) از قبل در مخزن است — **اول آنجا را بگردید** قبل از افزودن چیز جدید.
