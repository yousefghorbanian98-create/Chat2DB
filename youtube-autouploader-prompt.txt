## 1. PROJECT OVERVIEW & GOALS

Build a **Windows desktop application** that lets a user:

1. **Log in with their own Google account** (OAuth 2.0) and grant YouTube upload/read scopes.
2. **Paste a single YouTube video URL** from another channel -> the app downloads that video (best quality) and re-uploads it to the user's own YouTube channel — fully automated, no manual steps after confirmation.
3. **Paste a channel URL/handle** -> the app enumerates all public videos on that channel, lets the user pick which ones, and batch-downloads + re-uploads them.
4. **Auto-sync mode**: the user adds one or more channels to a "watch list"; a background monitor checks on a configurable schedule (1h / 6h / 12h / 24h); every new video uploaded to those channels is automatically downloaded and either (a) queued for approval or (b) immediately uploaded to the user's channel, depending on user setting.
5. **AI Clipping**: the user provides a long video (URL or local file); a **local LLM running via Ollama** identifies the most viral/highlight/jump-scare/controversial moments; the app auto-edits each highlight into a vertical 9:16 YouTube Short (with auto-captions, zoom-punch, background music, and auto-thumbnail), shows previews in the UI, and on user approval uploads each short to the user's channel.

**Non-goals / constraints:**
- The app MUST NOT require the user to write any code, run any terminal commands, or manually edit config files.
- The app MUST work fully offline for the AI clipping step (local Ollama; no cloud LLM calls).
- The installer MUST be a single `.exe` (NSIS) that bundles all required binaries (ffmpeg, ffprobe, yt-dlp).
- The app MUST run on Windows 10 (21H2+) and Windows 11, 64-bit only.
- **Copyright warning (display in app on first run)**: Re-uploading others' content may violate YouTube's TOS and copyright law; the user accepts full responsibility.

## 4. FEATURE #1 — GOOGLE OAUTH LOGIN

### 4.1 Credential model
- Do **NOT** embed any Client ID / Client Secret in code. On first launch the Settings page shows a guided wizard:
  1. Opens a link to `https://console.cloud.google.com/apis/credentials`
  2. Shows screenshots/step-by-step text for: create project -> enable YouTube Data API v3 -> create "OAuth 2.0 Client ID" (Desktop application type) -> add `http://localhost:5173/oauth2callback` (dev) and `http://127.0.0.1:{dynamicPort}/callback` (prod) to Authorized redirect URIs.
  3. Two masked inputs for Client ID and Client Secret with "Test & Save" button.
- Credentials stored via `keytar` under service name `YouTubeUploader/GoogleClientId` etc.
- Encrypted fallback to `app.getPath('userData')/secure.dat` (AES-256-GCM via Node `crypto` with machine-id key) if keytar unavailable.

### 4.2 OAuth flow
1. User clicks **"Sign in with Google"** (large, centered, Google-branded button).
2. Main process starts a temporary local HTTP server on a random free port (`127.0.0.1:0`) with a single `/callback` route.
3. Builds auth URL with scopes:
   - `https://www.googleapis.com/auth/youtube.upload`
   - `https://www.googleapis.com/auth/youtube.readonly`
   - `https://www.googleapis.com/auth/youtube.force-ssl`
   - `email`
   - `profile`
4. Opens `shell.openExternal(authUrl)` in user's default browser.
5. On callback, exchanges code for tokens; stores `access_token`, `refresh_token`, `expiry_date` in keytar.
6. Fetches user profile (`oauth2.userinfo.get`) and channel info (`channels.list(mine=true, part=snippet,statistics)`) and persists to DB settings.
7. IPC sends `auth:state-changed` event to renderer — app navigates to Dashboard.

### 4.3 Session
- On app start, if tokens exist and are expired, refresh automatically.
- If refresh fails (revoked), force logout and show Login page.
- Sidebar shows: profile picture (64px circular), channel name, email, sign-out button.

## 5. FEATURE #2 — SINGLE VIDEO UPLOAD BY URL

### 5.1 Input
- Prominent paste-area (large textarea with paste-icon) + "Paste from clipboard" button.
- URL validation (regex): accepts `youtube.com/watch?v=`, `youtu.be/`, `youtube.com/shorts/`, `m.youtube.com/`.
- "Fetch info" button auto-triggers on valid paste (debounced 500ms).

### 5.2 Metadata preview
After URL validation, app runs `yt-dlp -j <url>` to fetch JSON metadata and displays:
- Thumbnail (maxres default, fall back to hq -> mq)
- Title (editable input)
- Original channel name + link
- Duration (mm:ss)
- View count (formatted)
- Upload date
- Available qualities dropdown (default: `bestvideo[height<=1080]+bestaudio/best`; user can override to 720p/1440p/2160p)

### 5.3 Upload form
Editable before upload:
- Title (pre-filled, supports template tokens `{original_title}`)
- Description (textarea, template editor)
- Tags (chip input, comma-separated)
- Category (dropdown: 1-Film, 2-Autos, 10-Music, 15-Pets, 17-Sports, 20-Gaming, 22-People, 23-Comedy, 24-Entertainment, 25-News, 26-Howto, 27-Education, 28-Science)
- Privacy status: Public / Unlisted / Private (default from Settings)
- "Made for kids" toggle (default: off)
- Thumbnail override (file picker; default = source thumbnail)

### 5.4 Execution flow
1. User clicks **"Download & Upload"**.
2. Create job in DB (status `downloading`).
3. Invoke yt-dlp with:
   ```
   yt-dlp -f "<quality>" --merge-output-format mp4 ^
          --write-thumbnail --convert-thumbnails jpg ^
          -o "<tempDir>/%%(id)s.%%(ext)s" <url>
   ```
   Parse progress lines to emit `download:progress` IPC events (percent, speed, ETA).
4. On download complete, move to status `uploading`.
5. Call YouTube Data API `videos.insert` with `part=snippet,status` using resumable upload (chunk size 10 MB, report progress per chunk).
6. After successful upload, if custom thumbnail: `thumbnails.set(videoId, ...)`.
7. Status -> `success`; show Windows notification + in-app toast; delete temp files (unless Settings says keep); write `upload_history` row; open preview modal with embedded YouTube player.
8. Show "Copy link", "Open on YouTube", "Upload another" buttons.

## 7. FEATURE #4 — AUTO-SYNC (MONITOR & AUTO-UPLOAD)

### 7.1 Channel management
- "Add Channel" dialog with URL input (resolves like Section 6.1).
- Per-channel settings:
  - Check interval (1h / 6h / 12h / 24h / custom cron)
  - Auto-upload: On (instant) / Off (queue for approval)
  - Quality override
  - Title/description templates (override global)
  - Tags append
  - Privacy override
  - "Ignore shorts" / "Only shorts" toggle
  - Active/Paused switch

### 7.2 Monitor engine (`ChannelMonitor.ts`)
- Registers a `node-cron` job per active channel at its interval, OR uses a single tick-every-15-min job that dispatches due channels (recommended for simplicity).
- On each tick:
  1. Fetch latest uploads playlist ID via `channels.list(contentDetails)` -> `relatedPlaylists.uploads`.
  2. Call `playlistItems.list(playlistId=uploads, maxResults=20, order=date)` — compare video IDs against `synced_videos` table.
  3. For every new video (most recent first), insert a row with `status='pending'` and queue the download+upload job (or move to PendingApproval queue if auto-upload is off).
  4. Update `last_checked_at`.
- ETag/If-None-Match support to reduce quota usage.
- First-run behavior: do NOT backfill the entire channel history; only videos uploaded AFTER the moment the channel was added are auto-synced (with a one-time tooltip explaining this + optional "Backfill last N" button).

### 7.3 Lifecycle
- Starts automatically on app launch (if Settings `autoStartMonitor = true`).
- Runs even when window is closed (minimized to tray).
- Tray icon changes: gray = idle; blue = checking; green = uploading; red = error.
- Windows toast notification on each new detected video; click opens the app on that job's detail.
- Exponential backoff for per-channel failures (back-off 1h -> 4h -> 12h -> next scheduled run).

## 8. FEATURE #5 — LOCAL-LLM AI CLIPPING (HIGHLIGHTS / SHORTS)

### 8.1 Input page
- Two tabs: **YouTube URL** and **Local File**.
- Options panel:
  - LLM model dropdown (populated by `GET http://localhost:11434/api/tags`; mark recommended models with a star: `qwen2.5:14b-instruct`, `llama3.1:8b-instruct`, `gemma2:9b-instruct`).
  - Number of clips: slider 3-20 (default 5).
  - Max clip length: 15 / 30 / 60 / 90 sec (default 60).
  - Content category: Sports / Gaming / Educational / Vlog / Comedy / News / Challenge / Auto-detect.
  - Output aspect: 9:16 (Shorts/Reels/TikTok) / 1:1 / 16:9 (original).
  - Visual effects: [x] auto-captions (burned-in) / [x] smart zoom (Ken Burns / face-centered punch-in) / [x] background music (volume slider, default 12%) / [x] blurred background fill for portrait.
  - Auto-upload on approval checkbox (default off — user reviews each clip).

### 8.2 Prerequisites check
Before start, run these checks (show friendly status cards with fix buttons):
1. **Ollama reachable**: GET `http://localhost:11434/api/tags` with 2s timeout. If fail -> "Download Ollama" button opening `https://ollama.com/download/windows` + "Retry" button.
2. **Model available**: if the selected model is not in tags, offer to `ollama pull <model>` via streaming progress in the UI (stream `/api/pull`).
3. **ffmpeg present**: verify bundled binaries run (`ffmpeg -version`).
4. **Disk space**: warn if free space < 5 GB in temp dir.

### 8.3 Pipeline (`ClipperEngine.ts`)

Step 1 — Download / load video (same DownloadService as Section 5).

Step 2 — Audio analysis (ffmpeg):
- Extract mono 16kHz WAV: `ffmpeg -i in.mp4 -vn -ac 1 -ar 16000 audio.wav`
- Compute loudness/energy in 1-second windows with `ebur128` filter + `astats` to obtain per-second RMS peaks.
- Detect silence: `silencedetect=n=-30dB:d=0.8` to find pauses (used as safe cut points).

Step 3 — Scene detection (ffmpeg):
- `ffmpeg -i in.mp4 -filter:v "select='gt(scene,0.35)',showinfo" -f null - 2> scenes.log`
- Parse log to produce list of `(timestamp, scene_score)` tuples.

Step 4 — Transcription:
- **Primary**: try `yt-dlp --write-auto-sub --sub-langs en.*,fa.* --skip-download -o subs <url>`; if found, parse `.vtt` to array of `{start, end, text}`.
- **Fallback**: if Whisper binary bundled and model file present, run `whisper.cpp -m ggml-base.bin -f audio.wav -osrt -of out`; otherwise call Ollama if a whisper-family model is installed; otherwise show warning and use only scene+audio signals (still works, but less accurate).

Step 5 — Segment construction:
- Build candidate segments by splitting at scene changes and silence boundaries; cap each candidate at `max_clip_length` seconds.
- Score each candidate by:
  - `audio_peak_score` (normalized RMS max) -> 0-1
  - `scene_change_score` (density) -> 0-1
  - `speech_rate_score` (words per second from transcript, higher = more dynamic) -> 0-1
  - `keyword_score` from transcript (regex for: "wait", "oh my god", "wow", "look", "guys", "literally", "insane", "crazy", "never", "best", "worst", plus Persian equivalents if language detected).
- Keep top N segments (N = number_of_clips x 3) as candidates for LLM review.

Step 6 — LLM analysis:
- Build prompt:
  ```
  You are an expert short-form video editor.
  Given the transcript below and a list of candidate segments from a long-form video,
  select EXACTLY {N} clips that will be most engaging / viral as YouTube Shorts.
  Prioritize: emotional spikes, surprise, controversy, punchlines, game-winning moments,
  revelations, calls to action, funny moments.
  Content category: {category}.
  Maximum clip duration: {max_len} seconds.

  For each chosen clip return JSON with:
    - start: number (seconds, must match a candidate start exactly)
    - end:   number (seconds)
    - score: 1-10 (virality estimate)
    - title: string (<=70 chars, hook-style, no clickbait lies)
    - hook:  string (first 3 words the viewer sees; must grab attention)
    - hashtags: array of 3-5 relevant hashtags (no spaces, with #)
    - reason: one-sentence rationale

  Return ONLY a valid JSON object of shape { "clips": [...] } — no prose, no markdown fences.

  TRANSCRIPT:
  {transcript_with_timestamps}

  CANDIDATE SEGMENTS (start, end, audio_score, scene_score, keywords):
  {candidates_json}
  ```
- POST to `http://localhost:11434/api/generate` with `{model, prompt, stream:false, format:"json", options:{temperature:0.7, num_predict:2048}}`.
- Validate JSON (JSON.parse + zod schema `{clips: Array<{start:number,end:number,score:number,title:string,hook:string,hashtags:string[],reason:string}>}`); if invalid, retry up to 2 times with a stricter repair prompt.
- Merge LLM picks with audio/visual signals; clamp durations to `max_len`; snap cuts to nearest silence boundary within +/-2s.

Step 7 — Render each clip with ffmpeg:
- Cut lossless-cut first: `ffmpeg -ss {start-0.3} -to {end+0.3} -i in.mp4 -c:v libx264 -preset medium -crf 20 -c:a aac -b:a 192k -movflags +faststart raw_clip.mp4`
- Apply 9:16 portrait pipeline (if aspect=9:16):
  - Stack filter: `split[orig][bg];[bg]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,boxblur=20:1[bgf];[orig]scale=900:-1,format=yuv420p[fg];[bgf][fg]overlay=(W-w)/2:(H-h)/2`
  - If "smart zoom" enabled: add subtle `zoompan` or `scale+crop` that slowly zooms 100% -> 110% over clip length.
- Burn captions:
  - Build `.srt` file from transcript words/phrases that fall inside `[start,end]` (chunk at <=5 words per cue, phrase on word boundaries).
  - Style: `subtitles=clip.srt:force_style='FontName=Inter Bold,FontSize=22,PrimaryColour=&H00FFFFFF,OutlineColour=&H00000000,BorderStyle=1,Outline=3,Shadow=1,MarginV=110,Alignment=2'`
  - For Persian: use `Vazirmatn` and set `FontName=Vazirmatn`.
- Mix background music:
  - Loop bundled `background_lofi.mp3` to clip length; duck music during loud speech (use `sidechaincompress` filter with original audio as input, threshold=-20dB, ratio=4).
  - Final mix: `[voice][music]amix=inputs=2:duration=first:weights=1 0.15[out]`
- Output: `final_clip_{i}.mp4` (faststart, yuv420p).

Step 8 — Auto-thumbnail:
- Pick the frame with highest scene_score within the clip, or the frame at `start + (end-start)*0.3`.
- Extract with ffmpeg; composite via `sharp`: 1080x1920 gradient overlay at bottom, bold title text (70 chars max, 2 lines, white with black stroke), small channel badge top-left.
- Save `thumb_{i}.jpg`.

Step 9 — Persist clips in DB (`clips` table, status `pending`) and push to renderer via IPC as each clip finishes (user sees results streaming in, not waiting for all).

### 8.4 Preview & approval UI
- Grid of `ClipCard`s; each shows:
  - Inline HTML5 player (loop muted on hover; click to play with sound).
  - Title (editable), hashtags (editable chips), virality score badge.
  - Generated thumbnail preview.
  - Duration, file size.
  - Buttons: [Approve] / [Re-edit] (reopen in trim modal) / [Save As… local export] / [Regenerate title] / [Discard].
- Floating action bar: "Approve all", "Upload approved", "Discard all", "Export all to folder".
- Approve -> status `approved`; if auto-upload is on, immediately enqueue to UploadQueue with `type=clipper`.

### 8.5 Upload of shorts
- Use same upload flow as Section 5 but:
  - Append `#Shorts` to tags (YouTube requirement for Shorts detection).
  - Privacy defaults per Settings.
  - Set `selfDeclaredMadeForKids = false`.

## 10. IPC / PROCESS ARCHITECTURE

### 10.1 Process split
- **Main process**: ALL heavy work (network, filesystem, ffmpeg, yt-dlp, SQLite, Ollama, scheduler, tray).

## 12. ERROR HANDLING, RETRY & QUOTA

### 12.1 Retry policy (`utils/retry.ts`)
Generic `retry(fn, { attempts: 3, baseDelayMs: 2000, maxDelayMs: 60000, retryable: (err)=>bool })` with exponential backoff + jitter.

Retryable errors:
- Network errors / ECONNRESET / ETIMEDOUT / ENOTFOUND
- HTTP 5xx
- HTTP 429 (rate limit) — honor `Retry-After` header
- YouTube resumable upload 5xx / network interruptions (resume from last byte, not restart)
- Ollama 503 (model still loading) — wait longer, retry

Non-retryable errors (fail immediately, mark job, toast):
- 401 (auth expired and refresh failed -> force logout)
- 403 `quotaExceeded` -> pause all uploads, show banner, schedule resume for next day 00:00 Pacific
- 403 `uploadForbidden` (channel not eligible)
- 400 invalid request (bad video ID, malformed metadata)
- 409 duplicate (video already uploaded by user — treat as success if URL matches existing)
- Copyright strike/takedown during upload (status `rejected`, skip)
- Private/unavailable video from source

### 12.2 YouTube quota tracking
- Track API unit usage per day in DB key `quota_used_<YYYY-MM-DD>`.
- Upload = 1600 units; list/playlistItems = 1 unit/page; channels.list = 1; thumbnails.set = 50.
- Show remaining gauge on Dashboard (daily cap 10,000).
- When remaining < threshold (500 units), warn and ask to confirm before uploads.
- On quota exceeded, queue all future upload jobs with status `quota_wait` until next day.

### 12.3 Logging
- Winston-like simple logger: writes to file AND console; levels: error/warn/info/debug.
- All job stderr from ffmpeg/yt-dlp captured and attached to job_log for that job, viewable in UI via "Show log" drawer.
- On uncaughtException / unhandledRejection: write to crash log, show friendly "The app encountered an error" dialog with "Restart" / "Open log" / "Report (copy to clipboard)" buttons.

### 14.3 `electron/bin.ts`
```ts
import path from 'path';
import { app } from 'electron';
import { existsSync } from 'fs';

export function binaryPath(name: 'ffmpeg' | 'ffprobe' | 'yt-dlp') {
  const ext = '.exe';
  const base = app.isPackaged
    ? path.join(process.resourcesPath, 'binaries')
    : path.join(process.cwd(), 'resources', 'binaries');
  const p = path.join(base, `${name}${ext}`);
  if (!existsSync(p)) throw new Error(`Missing bundled binary: ${p}`);
  return p;
}
```
