## 2. موتورهای قطعی — نقطهٔ قوت پروژه

### JP7 (Jackson–Pollock 7-site)
با `Decimal` محاسبه می‌شود و به **fixtureهای معلوم‌الجواب** قفل شده:

| جنسیت | سن | Σ۷ (mm) | چگالی بدن | ٪چربی (Siri) |
|-------|-----|---------|-----------|---------------|
| مرد | 25 | 60 | 1.080674 | 8.0474 |
| مرد | 35 | 80 | 1.070632 | 12.3439 |
| زن | 25 | 60 | 1.067626 | 13.6453 |
| زن | 45 | 120 | 1.042926 | 24.6261 |

و یک **لنگر بیرونی**: مثال منتشرشدهٔ fitties.com (مرد، ۳۵، Σ=۱۰۷) → چگالی ۱.۰۶۱۶۶ که
کد دقیقاً بازتولید می‌کند. تیم حتی خطای حسابی خودِ آن منبع را مستند کرده است.

**این استاندارد طلایی است.** هر موتور عددی آینده (VO2max، ۱RM، نرخ پیشرفت) باید
همین‌طور به لنگر بیرونی بسته شود.

### تغذیه
`BMR = 370 + 21.6 × LBM` (Katch-McArdle)، فعالیت ×۱.۲–۱.۹، هدف ×۰.۸۵/۱.۰/۱.۱، پروتئین ۱.۸ g/kg LBM.
دستی راستی‌آزمایی شده: LBM 50.0857 → BMR 1451.85، TDEE ×1.55 = 2250.4، پروتئین 90.15.

🔴 **شکاف:** پایگاه غذای ایرانی خالی است. ورزشکار عدد کالری می‌گیرد ولی نمی‌داند چه بخورد.
این تنها چیزی است که تغذیه را از «ماشین‌حساب» به «محصول» تبدیل می‌کند.

### سازندهٔ برنامه مبتنی بر قاعده
همیشه در مسابقه با AI است (C7). اگر Ollama نباشد یا امتیاز بدتری بگیرد، قواعد برنده‌اند.
`/api/v1/ai/runtime` صادقانه گزارش می‌دهد که روی کدام مسیر است. **طراحی عالی.**

## 3. مغز AI — الگوی درست، اجرای اثبات‌نشده

```
اندازه‌گیری → برنامه‌ریزی (قواعد ∥ LLM) → اعتبارسنجی → امتیازدهی → dry-run → apply
```

قوانین محافظ که پیاده شده‌اند:
- LLM هرگز عدد تولید نمی‌کند (C6) — فقط ساختار و متن.
- خروجی در برابر **فهرست سفید عملیات** اعتبارسنجی می‌شود.
- فیلتر مصدومیت **بعد از** تولید هم اعمال می‌شود، نه فقط قبلش.
- `dry-run` اجباری، `apply` یک‌بارمصرف با ۴۰۹.

🔴 **آنچه اثبات نشده:** Ollama هرگز زنده اجرا نشده (باینری در محیط نبود).
یعنی مسیر AI فقط با mock تست شده. قبل از ادعای «AI کار می‌کند»، لازم است:
1. یک تست یکپارچگی با کانتینر Ollama در CI (مدل کوچک مثل `qwen2.5:0.5b`)؛
2. تست «تزریق پرامپت»: اگر LLM خروجی مخرب بدهد، اعتبارسنج آن را رد کند؛
3. سقف زمان و توکن، تا مدل کند کل درخواست را قفل نکند.

## 5. 🔴 شکاف‌های بک‌اند به ترتیب اهمیت

### 5.1 بدون محدودیت نرخ (بحرانی)
`grep -rn "rate.limit\|429" app/` → **صفر نتیجه**. PIN چهاررقمی + بدون قفل = شکستنی در ثانیه.
راه‌حل بدون وابستگی جدید: یک میان‌افزار با دیکشنری در حافظه + پشتوانهٔ SQLite برای دوام.

### 5.2 `audit_log` نوشته نمی‌شود (بحرانی برای انطباق)
جدول هست، صفر نویسنده. جزئیات در سند ۰۲ §۵.

### 5.3 بدون ابطال توکن
`jti` تولید می‌شود ولی ذخیره نمی‌شود. گوشی گم‌شده = ۸ ساعت دسترسی.

### 5.4 لاگ ساخت‌یافته نیست
`logging` متن ساده. برای عیب‌یابی از راه دور روی PC مشتری، JSON لازم است:
```python
{"ts":"...","level":"ERROR","request_id":"...","route":"/api/v1/payments","code":"..."}
```

### 5.5 بدون بررسی آمادگی (readiness) واقعی
`/health` زنده بودن را می‌گوید. یک `/ready` لازم است که بسنجد: DB قابل نوشتن است،
مهاجرت‌ها به‌روزند، فضای دیسک کافی است. برای نصب روی PC باشگاه (که دیسکش پر می‌شود) حیاتی است.

### 5.6 پشتیبان‌گیری خودکار زمان‌بندی‌شده نیست
API پشتیبان هست، ولی چیزی آن را هر ساعت صدا نمی‌زند. RPO یک‌ساعتهٔ سند ۰۱ اکنون
**تضمین نشده**. یک زمان‌بند داخل فرایند (`asyncio` task) + چرخش ۳۰ نسخه‌ای لازم است.

### 5.7 `VACUUM INTO` برای پشتیبان اتمی
کپی فایل SQLite حین نوشتن = پشتیبان خراب. از `VACUUM INTO 'backup.db'` استفاده کنید
که اتمی و سازگار است.

## 7. تفکیک محیط تولید از توسعه

اکنون `run.sh` تک‌کارگره uvicorn است. برای تولید:

| موضوع | توصیه |
|-------|--------|
| کارگرها | ۲–۴ کارگر uvicorn پشت یک فرایند سرپرست؛ با SQLite حواستان به `busy_timeout` باشد |
| راه‌اندازی خودکار | سرویس ویندوز (NSSM) یا Task Scheduler — نه پنجرهٔ CMD باز |
| چرخش لاگ | `RotatingFileHandler` ۱۰MB × ۵ — وگرنه دیسک PC باشگاه پر می‌شود |
| توقف مؤدبانه | مدیریت SIGTERM تا checkpoint شدن WAL |
| اتصال به ۱۲۷.۰.۰.۱ | پیش‌فرض درست است ✅؛ ۰.۰.۰.۰ فقط با تصمیم صریح و فایروال |

## 8. اگر از صفر می‌ساختید — چه چیزی را نگه دارید

سه تصمیم که در بازسازی هم باید تکرار شوند:

1. **ریاضی قطعی، جدا از AI، با fixture معلوم‌الجواب.** این چیزی است که محصول را
   از یک «چت‌بات ورزشی» به یک ابزار حرفه‌ای تبدیل می‌کند.
2. **dry-run → apply با ۴۰۹.** برای هر عملیات مخرب.
3. **ماسک میدانی سمت سرور.** حریم خصوصی که در UI اعمال شود، حریم خصوصی نیست.

و یک تصمیم که باید عوض شود: **بدون pydantic-settings ماندن** توجیه داشت
(«نصب روی PC ایزوله»)، اما اکنون `pydantic` خودش وابستگی است. استفاده از
`pydantic-settings` هزینهٔ جدیدی ندارد و اعتبارسنجی پیکربندی را رایگان می‌دهد.
