## Dual-shell layout rules

### MP Studio (coach / owner)
- Super-app **launcher grid** (like mockup 01) on home
- Dense side-nav optional after first click into module
- Always show **Safety card** on member profile if injury active
- Financial numbers only for OWNER/ADMIN
- AI dry-run panel before Apply (CE brain pattern)

### MP Client (athlete)
- Mobile-first bottom nav ≤ 5 items: Home · Workout · Nutrition · QR · Profile
- Touch targets ≥ 44×44 (Pro Max UX)
- Never show other members
- Injury notes: only `member_visible_note`
- Large QR for check-in

### Kiosk
- One job: scan + result. No chrome, no settings, idle timeout → lock

## Motion (Pro Max stagger, toned for dashboard)

- Launcher tiles: stagger 40–60ms, y:12, **no back.out** on dense tables
- Page transitions: 200ms fade
- Always honor `prefers-reduced-motion: reduce`
- Check-in success: one short scale pulse (150ms), then settle

```js
// Launcher only
gsap.from('.tile', {
  opacity: 0, y: 12, duration: 0.35,
  stagger: 0.05, ease: 'power2.out'
});
```

## RTL / i18n
- Full RTL when `fa`
- Numbers in JP7 stay LTR tabular (`dir="ltr"` on numeric fields)
- Dates: Jalali primary in FA locale, Gregorian secondary

---

## Anti-patterns (Do NOT)

- ❌ Generic orange “energy gym” palette (overridden — use emerald/gold)
- ❌ Emoji as icons
- ❌ Missing `cursor:pointer` on clickables
- ❌ Hover-only critical actions (kiosk/touch)
- ❌ Instant state changes (0ms)
- ❌ Invisible focus rings
- ❌ Showing other members’ data in Client
- ❌ AI apply without dry-run in Studio
- ❌ Low-contrast glass text (must ≥ 4.5:1)
- ❌ Scale transforms that shift layout on table rows
