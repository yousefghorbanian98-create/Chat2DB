# LOOP F — کیوسک، تبلت ورودی و تشخیص چهره
## ۲۴ تسک · ~۳ هفته · وابسته به LOOP C و D

**هدف:** تبلت دم در ورودی باشگاه که ورزشکار با **چهره** یا **QR** وارد شود.

---

## ⚠️ خواندن اجباری قبل از شروع

**تشخیص چهره بخش آسان است. تشخیص زنده‌بودن (liveness) بخش سخت است.**

بدون liveness، این حمله در ۱۰ ثانیه کار می‌کند:
```
عکس عضو از اینستاگرام → نمایش روی گوشی → جلوی تبلت → در باز می‌شود
```
اگر فقط تشخیص چهره را بسازید و liveness را نه، **یک سیستم امنیتی نساخته‌اید**.
تسک‌های F-15 تا F-18 غیرقابل‌حذف‌اند.

**قانون دوم:** QR همیشه به‌عنوان جایگزین فعال می‌ماند. FRR هرگز صفر نیست —
عضو با آرایش تازه، عینک نو یا نور بد باید بتواند وارد شود. بدون این، صف جلوی در.

**معیار پذیرش عددی (از `00_MASTER_ARCHITECTURE.md` §6.2):**
```
FAR < ۰.۰۱٪ · FRR < ۳٪ · شکست ضدجعل < ۱٪ · اسکن تا در < ۱ ثانیه · ۲۰۰۰ قالب
```

# فاز F1 — کیوسک QR (تسک ۰۱–۰۸)

> QR **اول** ساخته می‌شود چون تکیه‌گاه سیستم است. اگر چهره خطا داد، این کار می‌کند.

## F-01 · حالت کیوسک قفل‌شده
| **فایل‌ها** | `src/pages/kiosk/KioskShell.tsx` |
|---|---|
تمام‌صفحه · بدون ناوبری · بدون بازگشت · **خروج فقط با PIN** ·
جلوگیری از منوی راست‌کلیک و کشیدن.

## F-02 · اسکن پیوستهٔ QR
دوربین همیشه فعال · تشخیص خودکار · **بدون نیاز به لمس**.
اندروید: `barcode-scanner` · دسکتاپ: `getUserMedia` + `BarcodeDetector` (D-11).

## F-03 · بازخورد فوری
| هدف | < ۲۰۰ ms از اسکن تا نمایش |
|---|---|
✅ سبز: «خوش آمدی نسیم» · ❌ قرمز: «عضویت منقضی شده» · ⚠️ کهربایی: «۳ روز تا انقضا»
بازخورد **صوتی و بصری** — ورزشکار ممکن است صفحه را نبیند.

## F-04 · حریم خصوصی روی صفحهٔ عمومی
نام کوچک + بازگشت خودکار پس از **۸ ثانیه**.
هرگز روی کیوسک: شمارهٔ تلفن · مبلغ بدهی · اطلاعات سلامتی.
> این محدودیت مقرراتی نیست — **عرف حرفه‌ای** است. صفحهٔ ورودی را همه می‌بینند.

## F-05 · جلوگیری از اسکن تکراری
همان عضو در ۳۰ ثانیه → «قبلاً ثبت شد»، نه ردیف دوم. با `Idempotency-Key` (B-05).

## F-06 · حالت آفلاین کیوسک
هسته در دسترس نبود → ثبت محلی در صف + همگام‌سازی بعدی.
**قطعی شبکه نباید جلوی ورود را بگیرد.**

## F-07 · دسترس‌پذیری کیوسک
هدف لمسی ≥ **۶۰ px** (دست عرق‌کرده، عجله) · کنتراست بالا · متن بزرگ · بازخورد صوتی.

## F-08 · تنظیمات کیوسک در Studio
انتخاب دوربین · مدت نمایش · متن خوش‌آمد · PIN خروج · آستانهٔ تطبیق چهره.

# فاز F2 — زیرساخت دادهٔ بیومتریک (تسک ۰۹–۱۲)

## F-09 · جدول `member_biometrics`
| **فایل‌ها** | `app/migrations/v010_biometrics.py` |
|---|---|
```sql
CREATE TABLE member_biometrics (
  id, gym_id, created_at, updated_at, deleted_at, rev,
  member_id     INTEGER NOT NULL REFERENCES members(id) ON DELETE CASCADE,
  kind          TEXT NOT NULL,        -- 'face_v1'
  embedding     BLOB NOT NULL,        -- بردار ۵۱۲ بُعدی، رمزشده
  model_version TEXT NOT NULL,        -- برای مهاجرت هنگام تعویض مدل
  quality_score REAL,                 -- کیفیت ثبت‌نام
  enrolled_at   TEXT NOT NULL,
  revoked_at    TEXT
);
CREATE INDEX idx_biometrics_gym_kind ON member_biometrics(gym_id, kind, revoked_at);
```
**چرا جدول جدا:** حذف بیومتریک نباید به رکورد عضو دست بزند.
**چرا `model_version`:** روزی مدل عوض می‌شود؛ باید بدانید کدام قالب با کدام مدل ساخته شده.

## F-10 · رمزنگاری قالب‌ها در حالت سکون

## F-11 · API ثبت‌نام و حذف

# فاز F4 — یکپارچه‌سازی و سنجش (تسک ۲۱–۲۴)

## F-21 · جریان ورود با چهره در کیوسک
```
دوربین → تشخیص → liveness → بردار → تطبیق → آستانه → ثبت حضور
   │
   └─ هر مرحله شکست خورد → پیام روشن + «از QR استفاده کنید»
```
**هرگز** نگویید «چهره تشخیص داده نشد» و کاربر را رها کنید — همیشه راه دوم را نشان دهید.

## F-22 · آستانهٔ قابل‌تنظیم و حالت سخت‌گیرانه
آستانهٔ شباهت در تنظیمات (پیش‌فرض محافظه‌کارانه).
**قانون:** در شک، **رد کنید** و QR پیشنهاد دهید. پذیرش اشتباه بدتر از رد اشتباه است.

## F-23 · سنجش FAR/FRR روی داده واقعی
| **فایل‌ها** | `scripts/measure_face_accuracy.py` |
|---|---|

اگر اهداف برآورده نشد → آستانه را سخت‌تر کنید و دوباره بسنجید.

## F-24 · بار و پایداری کیوسک

دوربین بعد از قطع/وصل بازیابی می‌شود.

# معیار خروج LOOP F
```
□ ۲۴ تسک DONE
□ اسکن QR تا بازخورد < ۲۰۰ ms
□ چهره: اسکن تا در < ۱ ثانیه
□ FAR < ۰.۰۱٪ · FRR < ۳٪ (اندازه‌گیری‌شده، نه تخمین)
□ شکست ضدجعل < ۱٪ روی ۶۰ نمونهٔ حمله
□ 🔴 عکس روی گوشی جلوی تبلت → رد می‌شود (تست دستی ضبط‌شده)
□ QR همیشه به‌عنوان جایگزین کار می‌کند
□ دکمهٔ «چهره‌ام را حذف کن» → قالب فوراً پاک
□ قالب‌ها روی دیسک رمزشده‌اند
□ ۲۰۰۰ قالب → تطبیق < ۵۰ ms
□ ۸ ساعت اجرای پیوسته بدون نشت حافظه
□ عکس خام بعد از ثبت‌نام روی دیسک نمانده (تست)
```

**عدد:** `روش‌های ورود: ۱ → ۲` · `FAR/FRR: نامعلوم → عدد` · `زمان ورود: نامعلوم → < ۱ ثانیه`
