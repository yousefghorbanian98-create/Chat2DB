────────────────────────────────────────────
۱) اول: مرورگر را واقعاً راه بینداز (باز کردن قفل WEB)
────────────────────────────────────────────
وظیفه: در همین sandbox مرورگر headless را نصب کن و روی build واقعی Studio اجرا کن.

      cd /tmp && mkdir -p mp-browser && cd mp-browser
      npm init -y >/dev/null
      npm i playwright-core@latest @sparticuz/chromium@latest axe-core@latest

      # build واقعی Studio
      cd <repo>/mp-app/studio && npm ci && npm run build
      npx vite preview --host 0.0.0.0 --port 4173 &
      # یا: npx serve dist -l 4173

      # اسکریپت اجرا (نمونهٔ حداقلی)
      cat > /tmp/mp-browser/run.mjs <<'JS'
      import chromium from "@sparticuz/chromium";
      import { chromium as pw } from "playwright-core";
      const exe = await chromium.executablePath();
      const browser = await pw.launch({ executablePath: exe, args: chromium.args, headless: true });
      const page = await browser.newPage({ viewport: { width: 1440, height: 900 } });
      const errors = [];
      page.on("pageerror", e => errors.push(String(e)));
      await page.goto("http://127.0.0.1:4173/login", { waitUntil: "networkidle" });
      const dir = await page.evaluate(() => document.documentElement.dir);
      console.log("dir:", dir, "| pageerrors:", errors.length);
      await browser.close();
      JS
      node /tmp/mp-browser/run.mjs

  اگر این کار کرد، برای هر کدام از WEB-02…WEB-11 یک خروجی واقعی بگیر:
    - WEB-02: `page.goto` مستقیم روی `/staff/analytics` بدون session → باید به
      `/login` برود و محتوای خصوصی نشان ندهد. سپس back/forward و reload.
    - WEB-04: axe-core روی همان صفحه؛ گزارش violations با severity.
    - WEB-08: `navigator.serviceWorker` + خواندن manifest + بررسی icon/scope.
    - WEB-09: پس از logout و با دو حساب ساختگی، cache را بازرسی کن:
      هیچ API/PII/receipt در cache نماند.
    - WEB-10: worker در waiting بماند؛ دکمهٔ update رفتار درست بدهد.
    - WEB-11: با nginx واقعی (اگر نصب‌شد) یا `vite preview` SPA fallback را
      برای deep link و `/api` جدا آزمون کن.
  هر نتیجه را در `evidence/<DATE>/WEB-xx/browser-<view>.txt` بگذار.

  ⚠ اگر نصب یا اجرا واقعاً شکست خورد، متن دقیق خطا را در evidence بنویس
    (مثلاً `libnspr4.so` missing) و BLOCKED بزن — نه «در sandbox موجود نیست».
    تفاوت این دو مهم است: یکی شاهد است، یکی فرض.

────────────────────────────────────────────
۲) STATE را با واقعیت هم‌تراز کن
────────────────────────────────────────────
این خطوط را در STATE اصلاح/اضافه کن:
      BROWSER_AVAILABLE=yes|no  + دلیل دقیق (خطا یا نسخه)
      WEB_CHECKED_BY_BROWSER=<لیست IDها>
      CODE_OR_TEST_CHANGED_THIS_CYCLE=yes|no
و در بخش WEB بنویس: «مرورگر با Playwright/@sparticuz در همین sandbox اجرا شد
و خروجی در evidence/... است» یا «اجرا شد و شکست خورد با خطای X».

────────────────────────────────────────────
۳) v2: دو محدودیت باقی‌مانده را با کد حل کن، نه با یادداشت
────────────────────────────────────────────
  الف) `dynamic_sites=0` → الگوی regex فعلی در template interpolation می‌شکند.
       اصلاح لازم: در `crosswalk_v2.py` قبل از regex، template را به یک شکل
       canonical تبدیل کن:
         `${API_BASE}/members/${id}/checkins`  →  `/api/v1/members/*/checkins`
       یعنی هر `${...}` داخلی به `*` تبدیل شود، نه اینکه کل رشته قطع شود.
       سپس `dynamic_sites` باید > ۰ شود و اگر مسیری با `*` به هیچ route واقعی
       نخورد، `DYNAMIC_UNCOVERED` تولید شود.

  ب) تفکیک «مصرف‌کنندهٔ عضو» از «پنل کارکنان» دستی مانده.
       حداقل یک improvement انجام بده: هر call-site را با importهای همان فایل
       به کامپوننت/صفحه نسبت بده (کدام صفحه این تابع را import می‌کند؟) و ستون
       `surface=member|staff|shared` اضافه کن. لازم نیست کامل باشد؛ باید
       تکرارپذیر باشد و در review.md صریح ثبت شود.

  بعد از اصلاح: `crosswalk_v2.py` را دوباره روی همان SHA اجرا کن و تفاوت
  اعداد v2↔v3 را در STATE ثبت کن. پیوستن به “PARTIAL_REVIEW” بدون تغییر کد
  کافی نیست.

۴) SEC-01: دو شکاف را ببند
────────────────────────────────────────────
  الف) تست منفی: STATE می‌گوید «۳ تست function» برای پنج حوزه.
       آیا این سه تابع در مخزن **commit‌شده** هستند یا در /tmp نوشته و اجرا شدند؟
       اگر commit نشده‌اند، آن‌ها شاهد قابل‌تکرار نیستند. آن‌ها را در
       `mp-app/backend/tests/integration/test_sec01_negative_owner.py` بگذار و
       با `python -m pytest` دوباره اجرا کن. هر تست باید:
         - fixture ساختگی داشته باشد (نه production data)
         - assert کند 403 دقیقاً برای A→B
         - یک case مثبت هم داشته باشد (A→A باید 200 بدهد) تا تست بی‌اثر نباشد

  ب) anonymous و grant منقضی در ماتریس نیست. حداقل:
       - یک ستون `anonymous` برای مسیرهای حساس
       - یک تست grant منقضی/لغوشده روی یکی از مسیرهای مالی
       بدون این‌ها SEC-01 بالاتر از PARTIAL نمی‌رود.

────────────────────────────────────────────
۵) هر چرخه یک تغییر کد یا تست
────────────────────────────────────────────
از این به بعد در گزارش، خط اجباری:

      CODE_CHANGED: <فایل‌ها> یا «هیچ»

اگر «هیچ» بود، فقط یک بار مجاز است در دو چرخهٔ متوالی. چرخهٔ سوم باید کد/تست
داشته باشد، وگرنه STATE را با `LOOP_STALLED=yes` علامت بزن و به WEB/SEC code
paths برگرد.
