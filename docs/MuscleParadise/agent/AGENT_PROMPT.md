# چرخهٔ کاری — این ۹ گام را در هر تسک تکرار کن

```
① PICK    اولین تسک READY از TASK_BOARD.md را بردار
          → وضعیتش را فوراً IN_PROGRESS کن

② READ    سند لوپ + فایل‌های ستون «فایل‌ها» را واقعاً باز کن و بخوان
          ⚠️ حدس نزن. اگر فایل را نخوانده‌ای، کدت حدس است نه مهندسی.

③ PLAN    ۳ تا ۷ خط بنویس: هدف / فایل‌ها / تست / ریسک
          اگر بیش از ۷ خط شد، تسک بزرگ است — بشکنش

④ TEST    تست بنویس و مطمئن شو قرمز است
          ساعت را فریز کن · منطقهٔ زمانی را فرض نکن · شبکه را mock کن

⑤ BUILD   کمترین کدی که تست را سبز کند. نه بیشتر.

⑥ VERIFY  دستور verify همان تسک را اجرا کن
          exit 0 → گام ⑧ · غیر صفر → گام ⑦

⑦ HEAL    حداکثر ۳ تلاش:
          تلاش ۱: پیام خطا را کامل بخوان، فرضیه بنویس، بسنج
          تلاش ۲: کوچک‌ترین بازتولید را پیدا کن، git diff بگیر
          تلاش ۳: git stash کن — بدون تغییرات تو سبز است؟
          هنوز قرمز؟ → BLOCKED + ERRORS.log + تسک بعدی

⑧ GATE    هر پنج دروازه باید سبز باشند (پایین)

⑨ COMMIT  ثبت + به‌روزرسانی TASK_BOARD.md با عدد اندازه‌گیری‌شده
```

## چهار استاندارد غیرقابل‌مذاکره

**① «کلاس جهانی» یعنی هر جزء کوچک، نه فقط کارکرد.**
تسک وقتی DONE است که علاوه بر سبز شدن verify، این‌ها هم برقرار باشند:
```
□ حالت loading / خالی / خطا دارد — نه فقط حالت موفق
□ میکرو-اینتراکشن دارد: فشردن دکمه پاسخ می‌دهد، عدد می‌چرخد نه می‌پرد
□ همهٔ زمان‌بندی‌ها از نردبان حرکت src/motion/ladder.ts می‌آید (C-29)
□ prefers-reduced-motion محترم است
□ در ۳۲۰px و در RTL نمی‌شکند
□ هیچ پرش چیدمانی (CLS) موقع آمدن داده
□ فقط transform/opacity انیمیت می‌شود — هرگز width/height/margin
□ روی CPU throttle ×۴ زیر ۵۵ fps نمی‌آید (گیت C-35)
```
منابع الهام بصری: **Vengeance UI · Origin UI · Skiper UI · 21st.dev** — نگاه کن،
الگو را **بازنویسی** کن، ولی `npm install` نکن (RTL بومی ندارند).
منبع اول و اجباری: `docs/MuscleParadise/tools/ui-ux-pro-max/data/`
(`motion.csv` ۱۷ الگو · `react-performance.csv` ۴۴ ردیف · `ui-reasoning.csv`).
⚠️ **زیبایی‌ای که کند باشد، زشت است.** اگر گیت C-35 قرمز شد، انیمیشن را ساده کن.

**② هر برنامه باید با وصلهٔ تفاضلی به‌روز شود.**
هیچ‌کس نباید برای یک اصلاح کوچک، ۹۰ MB دوباره دانلود کند.
`LOOP_D_SHELL_TAURI.md` فاز D4 (تسک D-23…D-30): لایه‌بندی مصنوع، مانیفست
هش‌دار امضاشده، وصلهٔ `zstd --patch-from`، اعمال **اتمی** با بازگشت خودکار،
و بستهٔ دانش که مستقل از نسخهٔ برنامه به‌روز می‌شود.
**هدف عددی: وصلهٔ یک انتشار معمولی < ۵ MB و نصب < ۳۰ ثانیه.**
⚠️ به‌روزرسان تنها بخشی است که اگر خراب شود، با به‌روزرسانی درست نمی‌شود.

**③ انتقال داده بین مربی و شاگرد باید آفلاین و رایگان کار کند.**
سرور ابری مشترکی وجود ندارد. سه لایه بر اساس حجم (فاز B5 · تسک B-25…B-30):
```
لایه ۱ — QR      < ۶۶۶B   ارزیابی، برنامه، تغذیه   حتی از روی کاغذ چاپی
لایه ۲ — فایل    هر حجمی  پروندهٔ .mpx             بلوتوث/USB/پیام‌رسان
لایه ۳ — LAN     هر حجمی  همگام‌سازی کامل          وقتی هر دو در باشگاه‌اند
```
هر سه از **یک پاکت امضاشده و یک منطق اعتبارسنجی** استفاده می‌کنند.
⚠️ درون‌ریزی **هرگز** مستقیم نمی‌نویسد — همیشه پیش‌نمایش تفاوت و تأیید کاربر (C-39).
⚠️ دادهٔ فرستادهٔ شاگرد `source='self_reported'` علامت بخورد، وگرنه آمار باشگاه بی‌اعتبار می‌شود.

**④ مغز AI: LLM هرگز عدد تولید نمی‌کند.**
وضعیت امروز: `race()` و `judge_score()` در `ai_brain.py` نوشته و تست شده‌اند
ولی **هیچ‌جا صدا زده نمی‌شوند**؛ ستون `judge_score` همیشه NULL است؛
**هیچ پرامپتی در مخزن وجود ندارد**. فاز B6 (تسک B-31…B-40) وصلش می‌کند.
**یک مغز، روی PC ادمین.** سه اپ دیگر مدل اجرا نمی‌کنند — از LAN صدا می‌زنند.
اجرای مدل روی گوشی = ۵ گیگ دانلود و ۳–۶ دقیقه انتظار؛ همان کار روی PC با
GPU در ۱۵ ثانیه. صف تک‌کارگر (B-46) چون GPU همزمانی ندارد.
```
JP7 · TDEE · ماکرو · درصد چربی   → همیشه کد قطعی، هرگز LLM
برنامهٔ تمرینی                    → مسابقهٔ قاعده در برابر LLM، داور تصمیم می‌گیرد
تحلیل پیشرفت (اعداد)             → ریاضی قطعی در core/progress.py
متن تحلیل و انگیزشی              → LLM، ولی اعداد جای‌گذاری می‌شوند
```
⚠️ اگر LLM عددی نوشت که در ورودی نبود، **کل پاسخ را دور بریزید**.
🔴 **موتور: llama.cpp، نه Ollama.** Ollama برای گرفتن مدل مجبور است به
`registry.ollama.ai` وصل شود که در ایران مسدود است. llama.cpp **رجیستری ندارد** —
فایل `.gguf` را از هر جا بگیرید و `-m model.gguf` بدهید. اجرا کاملاً آفلاین است.
منابع مدل به ترتیب: **ModelScope → Gitee AI → HF-Mirror → aliendao**، و همیشه
**نصب دستی فایل** به‌عنوان تضمین (E-19). هیچ سناریویی نباید بن‌بست باشد.
⚠️ لایهٔ `llm_client.py` مستقل از موتور بماند تا کسی که Ollama دارد هم وصل شود.
⚠️ خروجی ساختاریافته با `json_schema` خودِ سرور اجبار شود؛ Outlines/Instructor/
LangChain **اضافه نکنید**.
⚠️ هیچ PII در پرامپت — حتی با مدل محلی (C10).
